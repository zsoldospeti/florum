MI ÚJ EBBEN A VERZIÓBAN?
  A Florum teendőit naptárfájlba (.ics) írja, amit a KDE
  panel Digitális órája eseményként tud mutatni – és
  figyelmeztetni is tud rájuk.

  * GITHUB – VERZIÓKÖVETÉS ÉS FRISSÍTÉS (1.33.2)
    A program felkerülhet GitHubra (privát repó), és
    onnantól a frissítés egy parancs. A növényeid,
    méréseid, fotóid NEM mennek fel (a .gitignore kizárja).

    Egyszeri beállítás:

        cd ~/florum
        bash florum-kiadas.sh --git-elokeszites
        git remote add origin \
            git@github.com:FELHASZNALONEV/florum.git
        git push -u origin main

    Új verzió kiadása (verzió mindenhol + build + teszt + zip):

        bash florum-kiadas.sh --uj 1.33.3 --epit --csomag
        bash florum-kiadas.sh --feltoltes

    Frissítés a gépeden:

        cd ~/florum && git pull && bash florum-frissites.sh

    Dockerben: bash docker/florum-docker.sh frissit
    Arcane: Git Syncs → a repó → Auto Sync.
    Részletek és hibaüzenet-táblázat: README 24. fejezet.

  * DOCKER + ARCANE – FRISSÍTÉS ADATVESZTÉS NÉLKÜL (1.33.2)
    A Florumhoz kész Docker-kép és Arcane-barát compose fájl van:

        docker/Dockerfile        a kép (nem root, /data kötet, healthcheck)
        docker/compose.yaml      docker compose / Arcane stack
        docker/florum-docker.sh  egyparancsos segéd

    A LÉNYEG: az adat köteten legyen, ne a konténerben.

        volumes:
          - ./data:/data

    Frissítés (a legegyszerűbb ma este):

        unzip -o florum-1.33.2-tiszta.zip -d ~/florum-uj
        cd ~/florum-uj/florum
        bash docker/florum-docker.sh frissit

    Vagy Arcane-ban: Git Syncs → repository + docker/compose.yaml → Auto Sync.
    Attól kezdve egy git push = új verzió, az adat megmarad.

    Hasznos parancsok:
        bash docker/florum-docker.sh allapot     (fut-e, hol az adat, mekkora)
        bash docker/florum-docker.sh mentes      (ZIP a kötetből, frissítés előtt)
        bash docker/florum-docker.sh ellenorzes  (a futó példány /api/info-ja)

    FIGYELEM: Arcane-ban a „container restart" NEM frissít – a régi képet
    indítja újra. A stacket kell újraépíteni (Rebuild/Pull).

    HA EZT ÍRJA: „Conflict. The container name /florum is already in use”
      → a régi konténer még létezik. NE töröld előbb! Előbb mentés:

        bash docker/florum-docker.sh atvesz

      Ez kimásolja a régi konténer adatait a docker/data mappába
      (és egyesíti, ha ott már van valami), kiírja hány növény/napló/mérés
      van benne, csak utána törli a régi konténert, és indítja az újat.

      Kézzel, lépésenként:
        bash docker/florum-docker.sh utkozes      (mi fut, hol az adat)
        bash docker/florum-docker.sh mentes-regi  (mentés)
        docker rm -f florum                       (csak ezután!)
        bash docker/florum-docker.sh indit
    Asztali értesítés (notify-send) konténerben nincs; a naptár .ics és a
    felület emlékeztetője viszont működik.

  * HŐMÉRSÉKLET MODUL – HELYISÉGENKÉNTI MÉRÉS (1.32.0)
    Új fül: Hőmérséklet. Ide írod be, amit a hőmérőn látsz –
    helyiségenként, naponta.

        Hőmérséklet fül → Mérés rögzítése
          · helyiség (a növények helyiségei + „Új helyiség”)
          · hőmérséklet (a magyar vessző is jó: 22,5)
          · páratartalom, nap, megjegyzés – nem kötelező
          · „Minden helyiség ma” – sorban bekéri a többit
          · CSV letöltés táblázatkezelőbe

    Mit számol belőle:
      · helyiségenként: mai érték, 7 és 30 napos átlag, hőingás,
        trend (melegszik / hűl), 14 napos kis grafikon
      · AZ ÖNTÖZÉS A MÉRÉSHEZ IGAZODIK, nem a naptárhoz és nem a
        havi átlaghoz: 28 °C-on egy 7 napos növény 5 napos lesz,
        18 °C-on egy 12 napos 14 napos
      · a trend is számít (a cserép földje lassan követi a szobát)
      · 10 napnál régebbi mérés nem számít – onnantól a havi átlag lép be

    Hol látszik még:
      · Ma fül: helyiségenként egy kocka a mai hőmérséklettel
      · Naptár (Nap/Hónap): a rács fölött havi hőmérséklet-sáv
      · Növények fül: „🌡 ×0,70” a kártyán
      · teendő-sor: „🌡 meleg szoba, hamarabb (×0,70)” + magyarázat

    A mérések a florum-data.json-ba mentődnek (max. 4000 mérés),
    és a florum-atkoltoztetes.sh is átviszi őket.

EVENT CALENDAR WIDGET – MIÉRT NEM MUTATOTT SEMMIT?
  A widget csak a SAJÁT adatmappájából hajlandó .ics fájlt olvasni
  (biztonsági ok): ~/.local/share/plasma_org.kde.plasma.eventcalendar
  Máshol ezt írja: „Local calendar file path is invalid”.
  A Florum 1.15.0 óta ezért minden mentésnél oda is ír másolatot:
    ~/.local/share/plasma_org.kde.plasma.eventcalendar/florum.ics
  A widgetben EZT az útvonalat add meg:
    Calendars → Add → ICS file → (a fenti útvonal)

  HA A WIDGET MÉGSEM MUTAT SEMMIT
  A widget beállítás-oldala CSENDBEN elutasítja a rossz útvonalat
  (a mező üresen marad), és akkor sem tölt be, ha a naptár
  nincs beikszelve, vagy hiányzik a Python-modul. Ezt egy
  lépésben ellenőrzi és javítja:

    bash kde-eventcalendar-diagnosztika.sh             (vizsgálat)
    bash kde-eventcalendar-diagnosztika.sh --javitas   (rendbetétel)
    bash kde-eventcalendar-fuggoseg.sh                 (Python-modulok)

  A --javitas biztonsági mentést készít, majd a Florum naptárát
  beírja a widget beállításába (helyes útvonal, show=true).

  MAGYAR FELIRAT A WIDGETHEZ
  Az Event Calendar plasmoidhoz nincs hivatalos magyar fordítás –
  ez a csomag pótolja (587/587 szöveg, 100%):
    bash kde-eventcalendar-magyar.sh
  A nyelvi fájl ide kerül:
    ~/.local/share/locale/hu/LC_MESSAGES/
      plasma_applet_org.kde.plasma.eventcalendar.mo
  Visszavonás: a .mo törlése + panel újraindítás.
